# Eat Wise: Project Documentation

This document provides a comprehensive overview of the Eat Wise application's architecture, features, and codebase.

## High-Level Overview

Eat Wise is a comprehensive health and fitness application designed to help users track their diet, exercise, and overall well-being.

### Core Features:

*   **Food and Calorie Tracking:** Log meals, track calorie intake, and view food history.
*   **Activity and Step Tracking:** Monitor physical activity and daily steps.
*   **Water and Weight Tracking:** Log water intake and track weight over time.
*   **Recipes and Meal Planning:** Browse recipes by category, diet, and meal type.
*   **Progress Monitoring:** Analyze and visualize progress towards health and fitness goals.
*   **User Authentication:** Secure user registration and login.
*   **Personalized Experience:** Onboarding for personalized plans and customizable settings.

## Project Structure

### `lib` Directory Structure

The `lib` directory is the heart of the Eat Wise application, containing all the Dart code for the user interface, business logic, and backend integration.

*   **`auth/`**: This directory contains all the logic related to user authentication. It interfaces with Firebase Auth to handle user sign-up, sign-in, and session management.

*   **`backend/`**: This directory is responsible for the application's backend services. This includes the Firebase integration, database schema, and any other backend-related logic.

*   **`buttons/`**: This directory likely contains custom button widgets used throughout the application, ensuring a consistent look and feel.

*   **`custom_code/`**: This directory is a placeholder for any custom Dart code that is not part of the main application structure. This can include utility functions, custom widgets, or any other code that doesn't fit into the other directories.

*   **`flutter_flow/`**: This directory contains code generated by or for FlutterFlow, a low-code platform for building Flutter applications. It likely includes UI components, themes, and utility functions provided by the framework.

*   **`home_pages/`**: This directory contains the main screens of the application, which are displayed after the user logs in. This is the central hub of the app.

*   **`pages/`**: This directory contains various other pages and screens of the application that are not part of the main home page structure.

*   **`profile/`**: This directory contains all the screens and logic related to the user's profile, including settings, preferences, and account management.

*   **`progress/`**: This directory holds the screens and widgets responsible for displaying the user's progress over time. This includes charts, graphs, and other data visualizations.

*   **`recipes/`**: This directory contains all the features related to recipes, including browsing, searching, and viewing recipe details.

*   **`register/`**: This directory handles the entire user registration and onboarding flow, from the initial welcome screen to creating a personalized plan.

*   **`tracker/`**: This directory contains the widgets and logic for the various trackers in the app, such as the step tracker, water tracker, and weight tracker.

### The `register` Module: User Onboarding and Authentication

The `register` directory manages the entire user journey from their first interaction with the app to having a fully set up account. This includes initial sign-up or login, password management, and the onboarding process to personalize their experience.

Each subdirectory typically contains a `_widget.dart` file, which defines the screen's UI, and a `_model.dart` file, which manages the screen's state.

*   **`entry_page/`**: This is the first screen the user sees. It likely presents the user with the choice to either log in to an existing account or sign up for a new one.

*   **`sign_up/`**: This screen contains the form for new users to create an account, asking for information like email, password, and name.

*   **`log_in/`**: This screen provides a form for existing users to sign in with their credentials.

*   **`reset_password/`**: For users who have forgotten their password, this screen starts the password reset process, usually by asking for their email address.

*   **`new_password/`**: This screen allows a user to set a new password after completing the password reset verification.

*   **`verify_code/`**: This screen is used to verify the user's email or phone number by asking them to input a code sent to them.

*   **`onboarding/`**: This is the start of the user onboarding flow. It might be a series of screens that gather information about the user's goals, preferences, and physical metrics.

*   **`get_started/`**: This screen is part of the onboarding process, likely a welcome screen that transitions the user into the main application after setup.

*   **`creat_plan/` (Create Plan):** This screen is a key part of onboarding where the app generates a personalized diet or fitness plan based on the information the user provided.

*   **`plan/`**: This screen likely displays the details of the generated plan to the user for their review.

*   **`components/`**: This directory contains reusable widgets used across the different screens of the `register` module.
    *   **`date_selector/`**: A widget for picking a date, likely for a user's birthday or goal deadlines.
    *   **`gender_info/`**: A widget to select the user's gender.
    *   **`review/`**: A widget for displaying information for the user to review.
